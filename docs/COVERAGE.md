# WCAG 2.2 coverage

What accessready does about each of the 86 level A and AA success criteria in WCAG 2.2. Generated from `src/coverage.mjs` and axe-core 4.14.0; do not edit by hand.

| | Criteria | What it means |
|---|---|---|
| **Checked** | 36 | At least one automated check can fail a page on this. It never covers the whole criterion; the last column says what is left. |
| **Listed for review** | 16 | Nothing is judged automatically, but the HTML report lists exactly what a person has to look at. |
| **By hand** | 25 | No tool support. A person has to test it. |

No automated tool can establish that a site conforms to WCAG. This table is here so you can see what a clean run does and does not tell you.

| Criterion | Level | Status | What is tested automatically | What a person still checks |
|---|---|---|---|---|
| 1.1.1 Non-text Content | A | Checked | Images, icons and image buttons that have no description at all. axe-core: `aria-meter-name`, `aria-progressbar-name`, `image-alt`, `input-image-alt`, `object-alt`, `role-img-alt`, `svg-img-alt`. | Whether each description says what the image is for. The report lists every image with its description. |
| 1.2.1 Audio-only and Video-only (Prerecorded) | A | Listed for review | Nothing. | Whether the transcript or description matches what is heard or seen. |
| 1.2.2 Captions (Prerecorded) | A | Checked | Video elements with no caption track. axe-core: `video-caption`. | Whether captions are accurate and complete, not only present. |
| 1.2.3 Audio Description or Media Alternative (Prerecorded) | A | Listed for review | Nothing. | Whether the description or text alternative covers everything shown that is not said. |
| 1.2.4 Captions (Live) | AA | By hand | Nothing. | Whether live captions keep up and are accurate. |
| 1.2.5 Audio Description (Prerecorded) | AA | Listed for review | Nothing. | Whether the audio description covers everything shown that is not said. |
| 1.2.6 Sign Language (Prerecorded) | AAA | Listed for review | Nothing. | Whether the sign language version is complete and well interpreted. |
| 1.2.7 Extended Audio Description (Prerecorded) | AAA | Listed for review | Nothing. | Whether pauses for extended description are long enough. |
| 1.2.8 Media Alternative (Prerecorded) | AAA | Listed for review | Nothing. | Whether the text alternative tells the whole story of the video. |
| 1.2.9 Audio-only (Live) | AAA | By hand | Nothing. | Whether the live text alternative keeps up with the audio. |
| 1.3.1 Info and Relationships | A | Checked | Broken list, table and ARIA structure. axe-core: `aria-hidden-body`, `aria-required-children`, `aria-required-parent`, `definition-list`, `dlitem`, `list`, `listitem`, `td-headers-attr`, `th-has-data-cells`. | Whether headings, lists and tables are marked up as what they look like. The report shows each page's heading outline. |
| 1.3.2 Meaningful Sequence | A | By hand | Nothing. | Whether the reading order makes sense in places the tool flags. |
| 1.3.3 Sensory Characteristics | A | By hand | Nothing. | Instructions the tool flags: is there also a text label to go by. |
| 1.3.4 Orientation | AA | By hand | Nothing. | Whether anything that does need one orientation (a piano app, a check deposit) is essential. |
| 1.3.5 Identify Input Purpose | AA | Checked | Invalid autocomplete values on form fields. axe-core: `autocomplete-valid`. | Whether each flagged field really collects the user's own details. |
| 1.3.6 Identify Purpose | AAA | By hand | Nothing. | Whether icons and regions are identified in a way assistive tools can adapt. |
| 1.4.1 Use of Color | A | Checked | Links inside text that differ from it by color alone. axe-core: `link-in-text-block`. | Color used as the only signal in charts and diagrams. |
| 1.4.2 Audio Control | A | Checked | Audio that plays by itself for more than three seconds with no way to stop it. axe-core: `no-autoplay-audio`. | Audio started by scripts in ways the tool did not trigger. |
| 1.4.3 Contrast (Minimum) | AA | Checked | Text contrast on solid backgrounds. Text over images, gradients and video, measured from a screenshot with the text hidden. axe-core: `color-contrast`. accessready: `contrast-on-image`. | Text over an image that passes in some places and fails in others. The report lists each one with its measured range. |
| 1.4.4 Resize Text | AA | Checked | Pages that block pinch-zoom. axe-core: `meta-viewport`. | Whether everything stays readable at 200% in the places the tool flags. |
| 1.4.5 Images of Text | AA | Listed for review | Nothing. | Whether flagged images of text are logos or essential. |
| 1.4.6 Contrast (Enhanced) | AAA | Checked | Text contrast on solid backgrounds at the enhanced ratio. axe-core: `color-contrast-enhanced`. | Text over images at the enhanced ratio, where the measurement is mixed. |
| 1.4.7 Low or No Background Audio | AAA | Listed for review | Nothing. | Whether speech in audio stands out from background sound by 20 decibels. |
| 1.4.8 Visual Presentation | AAA | By hand | Nothing. | Whether users can choose their own colors, and text width at 200%. |
| 1.4.9 Images of Text (No Exception) | AAA | Listed for review | Nothing. | Whether flagged images of text are logos or pure decoration. |
| 1.4.10 Reflow | AA | Checked | Sideways scrolling at 320px wide, with the widest element named. accessready: `reflow`. | Content that is hidden or overlaps at 320px wide without causing a scrollbar. |
| 1.4.11 Non-text Contrast | AA | Flagged for a person | The focused and unfocused screenshots are compared pixel by pixel; if no changed pixel reaches 3:1 against its unfocused color, the indicator is flagged. The browser default ring is not judged. accessready: `focus-indicator-contrast`. | Graphs and diagrams: does each part needed to understand them reach 3:1. |
| 1.4.12 Text Spacing | AA | Checked | Inline styles that force spacing. Text that is cut off once line, letter, word and paragraph spacing are widened to the values WCAG names. axe-core: `avoid-inline-spacing`. accessready: `text-spacing`. | Text that overlaps other content instead of being cut off. |
| 1.4.13 Content on Hover or Focus | AA | Checked | Tooltips and descriptions that appear on hover or focus and cover other content are tested with Escape, without moving the pointer. Content that appears on hover is checked again after the pointer moves from the trigger onto it. Content that appears on hover or focus is checked again after a second and a half with the pointer or focus still on the trigger. accessready: `hover-content-dismiss`, `hover-content-hoverable`, `hover-content-persistent`. | Popups the tool did not trigger. |
| 2.1.1 Keyboard | A | Checked | Scrollable regions and frames that the keyboard cannot reach. Controls with a click handler or an interactive role that the Tab key never reaches. Elements with a pointer cursor that Tab never reaches are noted for a person to try. Navigation menus are hovered, then the same is tried from the keyboard. Buttons that open something are pressed with Enter and Space as well as clicked. Focus is put on a tab or menu item and the arrow keys are pressed; if focus does not move, it fails when the other items are out of the Tab order, and is a note otherwise. Buttons that open a dialog are clicked, then Escape is pressed; a dialog that stays open is noted. axe-core: `frame-focusable-content`, `scrollable-region-focusable`, `server-side-image-map`. accessready: `keyboard-unreachable`, `looks-clickable`, `hover-only-menu`, `keyboard-activation`, `widget-arrow-keys`, `dialog-escape`. | Whether every custom widget (sliders, drag and drop, carousels) can be fully operated from the keyboard. |
| 2.1.2 No Keyboard Trap | A | Checked | An element that Tab and Shift+Tab cannot leave. accessready: `keyboard-trap`. | Traps inside widgets the walk did not open. |
| 2.1.3 Keyboard (No Exception) | AAA | Checked | Scrollable regions that the keyboard cannot reach. Controls with a click handler or an interactive role that the Tab key never reaches. Elements with a pointer cursor that Tab never reaches are noted for a person to try. Navigation menus are hovered, then the same is tried from the keyboard. Buttons that open something are pressed with Enter and Space as well as clicked. Elements that listen for a pointer press and pointer movement (drawing areas, signature pads) on a page where nothing listens for keys. Focus is put on a tab or menu item and the arrow keys are pressed; if focus does not move, it fails when the other items are out of the Tab order, and is a note otherwise. axe-core: `scrollable-region-focusable`. accessready: `keyboard-unreachable`, `looks-clickable`, `hover-only-menu`, `keyboard-activation`, `pointer-only-input`, `widget-arrow-keys`. | Whether any function at all needs a mouse or touch. |
| 2.1.4 Character Key Shortcuts | A | Flagged for a person | On pages with key handlers on the document, ten letter and punctuation keys are pressed one at a time in a fresh copy with focus on the page; any that load a page, move focus, scroll, open something or change the page are flagged. accessready: `character-shortcut`. | Whether flagged shortcuts can be turned off or remapped. |
| 2.2.1 Timing Adjustable | A | Checked | Pages that redirect or refresh on a timer. axe-core: `meta-refresh`. | Time limits after logging in, such as sessions that expire. |
| 2.2.2 Pause, Stop, Hide | A | Checked | Blinking and scrolling text. Video that plays by itself with no pause control. axe-core: `blink`, `marquee`. accessready: `moving-video`. | Animations and moving content the tool did not see start. |
| 2.2.3 No Timing | AAA | By hand | Nothing. | Whether timed steps are part of a real-time event. |
| 2.2.4 Interruptions | AAA | Checked | Pages that refresh or redirect by themselves. axe-core: `meta-refresh-no-exceptions`. | Interruptions that arrive after logging in. |
| 2.2.5 Re-authenticating | AAA | By hand | Nothing. | Whether data entered is kept when a session runs out and the user logs in again. |
| 2.2.6 Timeouts | AAA | By hand | Nothing. | Whether users are told how long data is kept when inactivity can lose it. |
| 2.3.1 Three Flashes or Below Threshold | A | By hand | Nothing. | Flashing in video that was not playing during the audit. |
| 2.3.2 Three Flashes | AAA | By hand | Nothing. | Flashing in video that was not playing during the audit. |
| 2.3.3 Animation from Interactions | AAA | By hand | Nothing. | Motion triggered by interactions the tool did not perform. |
| 2.4.1 Bypass Blocks | A | Checked | Pages with no skip link, landmarks or headings to jump past repeated content. The skip link among the first Tab stops is pressed with Enter, then Tab; it fails if its target does not exist or focus comes back before the target. axe-core: `bypass`. accessready: `skip-link-broken`. | Whether the skip link lands on the main content. |
| 2.4.2 Page Titled | A | Checked | Pages with no title. Different pages that share a title are noted. axe-core: `document-title`. accessready: `duplicate-title`. | Whether each title describes its page. |
| 2.4.3 Focus Order | A | Flagged for a person | The Tab sequence is compared with where each stop sits on the page: a positive tabindex that pulls elements ahead, or one stop far up or down the page between two neighbours, is flagged with the sequence. A dialog that opens without taking keyboard focus is noted. A dialog that took focus is opened and closed again; if focus does not come back to the button that opened it, it is flagged. accessready: `focus-order`, `dialog-focus`, `dialog-focus-return`. | Whether the Tab order makes sense in the places the tool flags. |
| 2.4.4 Link Purpose (In Context) | A | Checked | Links with no text at all. axe-core: `area-alt`, `link-name`. | Whether each link says where it goes in its context. The report lists links such as "click here" and "read more". |
| 2.4.5 Multiple Ways | AA | By hand | Nothing. | Pages that are steps in a process, which are exempt. |
| 2.4.6 Headings and Labels | AA | Listed for review | Nothing. | Whether headings and labels describe what follows. The report shows each page's heading outline. |
| 2.4.7 Focus Visible | AA | Checked | Every Tab stop is screenshotted focused and unfocused; if nothing on screen changes, it fails. Text fields whose only sign of focus is the text cursor are noted. accessready: `focus-visible`, `focus-caret-only`. | Focus indicators inside widgets the walk did not open. |
| 2.4.8 Location | AAA | By hand | Nothing. | Whether the user can tell where they are in sites without breadcrumbs or a marked current page. |
| 2.4.9 Link Purpose (Link Only) | AAA | Checked | Links with the same text that go to different places. axe-core: `identical-links-same-purpose`. | Whether each link makes sense read on its own. |
| 2.4.10 Section Headings | AAA | Listed for review | Nothing. | Whether long sections are organized by headings. |
| 2.4.11 Focus Not Obscured (Minimum) | AA | Checked | Every Tab stop is checked for being completely covered by something else or off screen. accessready: `focus-not-obscured`. | Elements that are mostly but not completely covered. |
| 2.4.12 Focus Not Obscured (Enhanced) | AAA | Checked | Every Tab stop is sampled at nine points; if some but not all are covered by other content, it is reported (a failure when the cover is a fixed or sticky element). accessready: `focus-partly-obscured`. | Widgets the walk did not open. |
| 2.4.13 Focus Appearance | AAA | Checked | The pixels that change by at least 3:1 between focused and unfocused are measured; together they must cover at least the area of a 2px outline around the element. The browser default ring, wrapped links and hidden inputs are not judged. accessready: `focus-appearance`. | Indicators inside widgets the walk did not open. |
| 2.5.1 Pointer Gestures | A | Flagged for a person | Carousels and sliders that listen for touch or pointer movement and have no previous, next or dot buttons. Elements that listen for pinch and rotate gestures and have no buttons nearby that could do the same. accessready: `swipe-only`, `multipoint-gesture`. | Whether flagged gestures have a single-tap alternative. |
| 2.5.2 Pointer Cancellation | A | Flagged for a person | Elements with a press handler are pressed and held in a fresh copy of the page; if they act before the button is released, and sliding off and letting go does not undo it, they are flagged. accessready: `down-event-action`. | Whether actions that fire on press can be aborted or undone. |
| 2.5.3 Label in Name | A | Checked | Buttons and links whose accessible name does not contain their visible text. axe-core: `label-content-name-mismatch`. | Nothing further in most cases. |
| 2.5.4 Motion Actuation | A | Flagged for a person | Pages that listen for device motion are shaken and tilted with sensor events in a fresh copy; if the page reacts, it is flagged. accessready: `motion-actuation`. | Whether flagged motion features have a button alternative and can be turned off. |
| 2.5.5 Target Size (Enhanced) | AAA | Checked | Every link, button and control is measured, its label included; anything under 44 by 44 CSS px fails unless it sits in a line of text, a larger target does the same thing, or it is a native checkbox or radio the browser sizes. accessready: `target-size-enhanced`. | Whether small targets are inline in text or have an equivalent larger target. |
| 2.5.6 Concurrent Input Mechanisms | AAA | Flagged for a person | Controls with touch handlers and no click, mouse or pointer handler anywhere above them. accessready: `touch-only`. | Whether the site works with a mouse and a touch screen on the same device. |
| 2.5.7 Dragging Movements | AA | Flagged for a person | Draggable elements, and elements that follow the pointer while pressed, that have no click handler and no buttons near them. accessready: `drag-only`. | Whether flagged drag features have a click or tap alternative. |
| 2.5.8 Target Size (Minimum) | AA | Checked | Buttons and links smaller than 24 by 24 pixels with no spacing around them. axe-core: `target-size`. | Nothing further in most cases. |
| 3.1.1 Language of Page | A | Checked | A missing or invalid page language. axe-core: `html-has-lang`, `html-lang-valid`, `html-xml-lang-mismatch`. | Whether the declared language is right where detection is unsure. |
| 3.1.2 Language of Parts | AA | Checked | Invalid language codes on parts of a page. axe-core: `valid-lang`. | Passages in another language too short for detection. |
| 3.1.3 Unusual Words | AAA | By hand | Nothing. | Whether flagged words are defined somewhere the user can find. |
| 3.1.4 Abbreviations | AAA | By hand | Nothing. | Whether flagged abbreviations are expanded somewhere the user can find. |
| 3.1.5 Reading Level | AAA | By hand | Nothing. | Whether a simpler version or summary is available for text above the reading level. |
| 3.1.6 Pronunciation | AAA | By hand | Nothing. | Words whose meaning depends on how they are pronounced. |
| 3.2.1 On Focus | A | Checked | During the Tab walk, a stop that loads another page, submits a form, opens a window or opens a dialog is noted, then confirmed in a fresh copy by focusing only that element. Page loads are answered with no content, so nothing leaves the page. Windows opened by a script while the page loaded, with no click or key press behind them. accessready: `focus-changes-context`, `window-opened-unasked`. | Changes of context on focus in widgets the walk did not open. |
| 3.2.2 On Input | A | Flagged for a person | Dropdowns, radio buttons and checkboxes outside login and payment forms are changed in a fresh copy; if that loads a page, submits the form or opens a window, it is flagged. Every page load and form submission is stopped before it reaches the server. accessready: `change-on-input`. | Changes the tool did not trigger, such as typing in a field. |
| 3.2.3 Consistent Navigation | AA | Checked | The main navigation is compared across every page audited; a page that lists the same links in a different order fails. accessready: `inconsistent-navigation`. | Other repeated blocks, such as footers and sidebars. |
| 3.2.4 Consistent Identification | AA | By hand | Nothing. | The same function labelled differently on different pages, beyond links. |
| 3.2.5 Change on Request | AAA | Checked | Pages that refresh or redirect by themselves. Links with a target that opens a new window or tab, whose text, label and icons do not mention it. Windows opened by a script while the page loaded, with no click or key press behind them. axe-core: `meta-refresh-no-exceptions`. accessready: `new-window-unannounced`, `window-opened-unasked`. | Changes of context that happen without being asked for. |
| 3.2.6 Consistent Help | A | By hand | Nothing. | Help mechanisms the tool does not recognize. |
| 3.3.1 Error Identification | A | Listed for review | Nothing. | Errors that only the server reports, after a real submission. |
| 3.3.2 Labels or Instructions | A | Checked | Fields with more than one label. axe-core: `form-field-multiple-labels`. | Whether labels and instructions are clear, including required formats. |
| 3.3.3 Error Suggestion | AA | Listed for review | Nothing. | Whether error messages say how to fix the problem. |
| 3.3.4 Error Prevention (Legal, Financial, Data) | AA | Listed for review | Nothing. | Whether legal, financial and data submissions can be reviewed, corrected or reversed. |
| 3.3.5 Help | AAA | By hand | Nothing. | Whether help is useful where it exists. |
| 3.3.6 Error Prevention (All) | AAA | Listed for review | Nothing. | Whether every submission can be reviewed, corrected or reversed. |
| 3.3.7 Redundant Entry | A | Listed for review | Nothing. | Multi-step processes that ask for the same information on a later step. |
| 3.3.8 Accessible Authentication (Minimum) | AA | By hand | Nothing. | Login flows behind the first screen, such as two-factor steps. |
| 3.3.9 Accessible Authentication (Enhanced) | AAA | By hand | Nothing. | Login flows behind the first screen. |
| 4.1.2 Name, Role, Value | A | Checked | Buttons, links, fields and frames with no name, and invalid ARIA roles and attributes. Buttons that control another element are clicked; if that element appears or disappears and aria-expanded does not change (or is missing), it is reported. Custom checkboxes and switches are clicked and screenshotted; if they look different afterwards but aria-checked has not changed, it is reported. Another tab in each tab list is clicked; if what is shown changes but aria-selected stays where it was, it is reported. axe-core: `area-alt`, `aria-allowed-attr`, `aria-braille-equivalent`, `aria-command-name`, `aria-conditional-attr`, `aria-deprecated-role`, `aria-hidden-body`, `aria-hidden-focus`, `aria-input-field-name`, `aria-prohibited-attr`, `aria-required-attr`, `aria-roles`, `aria-tab-name`, `aria-toggle-field-name`, `aria-tooltip-name`, `aria-valid-attr-value`, `aria-valid-attr`, `button-name`, `duplicate-id-aria`, `frame-title-unique`, `frame-title`, `input-button-name`, `input-image-alt`, `label`, `link-name`, `nested-interactive`, `select-name`, `summary-name`. accessready: `disclosure-state`, `toggle-state`, `tab-state`. | Whether custom widgets announce their state changes to a screen reader. |
| 4.1.3 Status Messages | AA | By hand | Nothing. | Status messages from actions the tool did not perform. |
